# GLM 核心规则

> 入口文件，GLM 自动加载

## 核心
- 按高并发后端工程处理
- 最小必要改动
- 优先复用现有实现
- 保持正确、可读、兼容、可编译
- 保持现有行为稳定
- 优先主流稳定分层与常用优秀设计模式

## 边界
- 不做无关改动
- 调整目录、边界、分层前先确认
- 不擅改公共接口、字段定义、错误语义、执行顺序
- 发现架构不适合高并发：先短建议，再等确认

## 方式
- 先看上下文、调用链、影响范围
- 先找相似实现
- 优先贴近现有项目习惯
- 确认后落实代码、测试、验证和真实说明

## 风格
- 命名延续 Go API 风格
- API 路径、JSON 字段、术语、缩写优先复用现有命名
- 保持现有代码组织、函数拆分、错误处理、返回值风格一致
- 保持注释、日志、字段顺序风格一致

## 风险控制
默认不做：
- 大重构
- 改目录或模块边界
- 改公共接口、字段名、tag
- 引第三方依赖
- 改并发模型
- 改事务、幂等、重试、回滚
- 改响应结构或错误语义

冲突时选：
- 更保守
- 更兼容
- 更小改动

## 高并发优先级
- 先消除重复计算：重复鉴权、重复 panic 恢复、重复 body 读取
- 再做链路治理：超时、限流、熔断、降级
- 最后做深度优化：缓存命中、批处理、连接池、热点拆分

- Go 代码：`.glm/go.md`
