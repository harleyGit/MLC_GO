# 00-core.md

## 核心目标
- 按生产级 Go 后端工程处理，优先正确性、兼容性、可编译、可验证和可维护
- 数据库、缓存、队列、外部 I/O、API 热点路径默认按高容量与失败模式评估，不按小表、低频或单机场景假设
- 修改前先理解任务、规则、上下文、调用链、相似实现和影响范围
- 优先复用现有实现和项目风格；不足时只做最小必要扩展
- 涉及 SQL / 数据 / 高并发 / 安全时，叠加对应模块规则执行

## 工作边界
- `/Users/ganghuang/HGFiles/GitHub/GoProject/src/MLC_GO/TestNotes/**` 为学习/示例文件，不纳入日常修改、编译、测试、lint、review 范围，默认不读取、不修改、不修复、不测试
- 除非用户明确要求处理 `TestNotes`，否则不要为了该目录的编译、测试、lint、review 失败调整业务代码或规则
- 不做无关改动
- 不擅改公共接口、字段定义、错误语义、执行顺序、事务语义
- 调整目录、模块边界、公共接口或新增重大依赖前先确认
- 发现现有实现不适合生产级要求时，能局部低风险修正则直接修正；需要大重构、改边界或改语义时先说明风险并等待确认

## 默认方式
- 修改前用搜索工具查定义、引用、影响范围和相似实现
- 小步修改，保持变更集中，不顺手重构无关代码
- 完成后格式化、自检、尽量编译/测试，并真实说明验证结果
- 连续 2 次编译、测试或修复失败时停止自循环，保留现场并说明阻塞点
