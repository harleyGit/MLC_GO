# 04-data-rules.md

## 数据层
- 数据访问层写法保持一致
- 所有增删改查默认面向亿级以上数据表，任何全表扫描、无索引过滤、深分页、长事务、热点行更新都按高风险处理
- 不擅改 SQL 语义、ORM 封装方式、repository / dao 职责边界
- CRUD 改动必须优先检查索引命中、分页方式、事务范围、批量策略、连接池压力、缓存一致性和并发安全
- 大流量写入链路检查热点行/索引、唯一键冲突、事务范围、连接池压力、批量写入策略、幂等与重试放大

## 亿级数据 CRUD 基线
- 查询必须先确认过滤字段、排序字段、Join 字段能命中合适索引；不确定时在说明中标注索引前提和风险
- 针对单表数据量千万级及以上的增删改查，必须在代码注释、实现说明或交付说明中明确索引命中、查询条件、分页策略、事务边界、批量策略和降级限制
- 分页优先使用游标、递增主键、时间游标或复合游标；避免大 offset 深分页
- 列表查询禁止默认返回无上限数据；必须有 limit、排序稳定性和最大页大小约束
- 更新和删除必须限制范围，优先主键、唯一键或索引范围；禁止无保护的大范围写操作
- 批量写入、更新、删除要分批执行，明确批大小、事务边界和失败重试策略
- 事务范围保持最小，只包裹必须原子一致的数据库操作；事务内避免外部 I/O、慢查询和不必要循环
- 统计、计数、排行榜、聚合类查询默认评估缓存、异步汇总、预聚合或离线任务，不直接假设实时全量聚合可承受
- 多表 Join 默认评估数据量、驱动表、索引顺序和结果集放大；大表 Join 优先考虑反范式、预计算或分步查询
- 写后读、缓存失效和异步任务必须说明一致性窗口；热点缓存要考虑击穿、穿透、雪崩和 key 倾斜

## SQL / ORM
- 查询风格保持一致，不因局部优化改变字段映射、筛选、排序、分页语义
- 事务沿用现有模式
- Go 业务代码中的固定 SQL 必须集中放入 `internal/pkg/mysql/queries/hg_sql_queries.go`，Repository / DAO 中只引用 SQL 常量；只有动态拼接的条件片段可以通过该文件中的 SQL 片段常量组合
- SQL 文件过大时允许按业务领域平行拆分，如 `user_queries.go`，但不得在 repository / dao / service / handler 中散写固定 SQL
- 新增或修改 SQL 常量时，优先在 SQL 常量旁写明用途、索引命中、分页策略、事务边界或降级限制；涉及千万级表时不得只在调用处解释
- 禁止在 Repository / DAO 中散落大段内联 SQL；如确需临时 SQL，必须写明原因和后续迁移到 `internal/pkg/mysql/queries/hg_sql_queries.go` 的条件
- SQL 改动必须同步检查字段类型、索引、外键和查询结果扫描顺序
- ORM 查询必须避免隐式全量加载、N+1 查询、无上限 preload、循环内查询和未限制字段选择

## 缓存
- Redis 字符串值若可能经 JSON 序列化后入库，读取后比较前先做解码兼容
- 影响查询结果的写操作后，按现有 key 规则清理单体、列表分页和 total 缓存
- 沿用现有延迟双删或消息驱动失效机制，不擅自更换一致性策略
- Redis 用于限流、幂等、锁、计数、会话状态时，明确 key、TTL、原子性、热点、失败和清理策略
- Redis key 前缀必须集中定义在 `internal/infrastructure/persistence/redis/hg_redis_key.go`，业务模块只组合具体业务 ID，不散落硬编码前缀
- Redis 多命令组合若影响一致性或并发正确性，优先用 Lua；脚本集中定义在 `internal/infrastructure/persistence/redis/hg_redis_script.go` 或同目录领域文件，并注释 KEYS/ARGV

## 兼容
- 不擅改数据库字段含义
- 不擅改 model 与库字段映射
- 不擅改序列化字段和 tag

## 模型
- 不混用数据库模型、接口模型、业务模型
- 不随意合并或拆分模型
- 模型字段新增、删除、改名必须同步检查数据库映射、API 映射、缓存序列化和迁移兼容
