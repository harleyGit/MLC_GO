# 05-validation.md

## 修改后必须自检
每次修改完成后，必须检查：
- 是否存在语法错误
- 是否存在编译错误
- 是否存在未使用 import
- 是否存在未使用变量
- 是否存在返回值不匹配
- 是否存在 nil 风险
- 是否存在接口实现不完整
- 是否存在调用链破坏
- 是否存在风格不一致问题

## 格式化要求
每次修改 Go 代码后，必须格式化。

默认要求：
- 至少执行 gofmt
- 若项目已有 goimports 习惯，则优先使用 goimports

优先格式化本次修改文件，减少无关改动。

## 编译检查
在条件允许时，尽可能执行：
1. 格式化修改文件
2. 检查 import 与语法
3. 优先编译受影响包
4. 必要时执行全量 go build ./...

## 测试检查
若项目已有测试：
- 优先运行受影响范围测试
- 改动较大时再考虑更大范围测试

## 不得伪造验证结果
- 未执行的 build / test / lint，不得说成已通过
- 未实际验证时，必须明确说明未执行及原因
