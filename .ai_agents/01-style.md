# 01-style.md

## 命名风格
- 方法名、变量名、结构体名、接口名、文件名、目录名应延续GO语言API风格。
- API 路径、JSON 字段、业务术语、缩写必须优先复用现有命名。

## 代码风格
- 保持当前工程已有的代码组织方式。
- 保持函数拆分习惯、错误处理风格、返回值风格一致。
- 保持已有注释、日志、结构体字段顺序风格尽量一致。

## 注释规则
- 新增注释时保持与项目现有注释风格一致，尽可能的详细。
- 注释只用于复杂逻辑、边界条件、兼容性说明。
- 不写无意义废话注释。
- 不删除已有有价值的业务注释。
- 新增或修改方法、函数时，必须补 1~2 行职责注释，至少说明“这个方法做什么”和“关键校验点/关键输入输出是什么”。
- 若方法承担鉴权、签名、防篡改、事务、重试、缓存等关键职责，注释中必须写明核心约束，避免后续维护误改。
- 对“关键入口交互逻辑”和“功能分发函数”必须补 1~2 行注释，说明职责与设计目的。
- 涉及 Shell、Bash、启动脚本、运维脚本时，注释应比普通代码更详细，便于不熟悉脚本的维护者阅读。
- 新增或修改脚本时，默认需要补充关键注释，不能只给结论不解释过程。

## 日志规则
- 日志风格、字段风格、日志级别应延续项目习惯。
- 不随意增加大量无价值日志。
- 不输出敏感信息。
