# 03-api-rules.md

## Handler / Controller
- 请求处理风格必须与当前项目一致。
- 不在 handler/controller 中引入明显超出当前风格的大量业务逻辑。
- 参数解析、参数校验、响应输出方式应统一。
- 错误码、响应结构、状态码使用遵循现有项目规范。

## Service
- service 层负责组织业务流程时，应保持逻辑清晰、边界明确。
- 不过度拆分 service。
- 不擅自改变业务执行顺序。
- 涉及事务、幂等、回滚、重试时，优先沿用项目已有模式。

## Request / Response
- 保持当前请求对象、响应对象定义方式一致。
- 不擅自修改 response 结构。
- 不擅自修改对外字段名。
- 不因为“更优雅”而改变 API 兼容性。

## 校验与错误返回
- 参数校验风格必须与项目一致。
- 错误返回格式、错误码、错误信息风格保持一致。
- 不新增与现有规范冲突的错误处理方式。
