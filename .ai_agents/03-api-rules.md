# 03-api-rules.md

## Handler
- 请求处理风格与当前项目一致
- 不在 handler 中堆过多业务逻辑
- 参数解析、校验、响应方式统一
- 错误码、响应结构、状态码沿用现有规范

## Service
- service 负责流程组织，边界清晰
- 不过度拆分
- 不擅改业务顺序
- 事务、幂等、回滚、重试沿用现有模式
- Redis 验证码等字符串校验时，若存在 JSON 序列化入库路径，先做解码兼容再比较
- 会影响列表查询结果的写操作后，及时清理对应列表缓存（分页 key + total key）

## Request / Response
- 保持现有定义方式
- 不改 response 结构
- 不改对外字段名
- 不为“更优雅”破坏兼容

## 校验与错误
- 参数校验风格一致
- 错误返回格式、错误码、错误信息风格一致
