# 03-api-rules.md

## Handler
- 请求处理风格与当前项目一致
- 不在 handler 中堆过多业务逻辑
- 参数解析、校验、错误码、状态码、响应结构沿用现有规范
- 高并发链路避免重复鉴权、重复恢复、重复读取 body
- 大文件/流式上传优先流式读取、限制 body 大小并处理取消
- 对外写接口考虑重复提交、幂等 token、用户/IP 限流和错误快速返回

## Service
- service 负责流程组织，边界清晰
- 不擅改业务顺序
- 事务、幂等、回滚、重试沿用现有模式
- 涉及缓存、限流、异步削峰时按 `04-data-rules` 与 `08-performance` 执行
- 外部 I/O、异步任务和状态写入要明确超时、取消、失败处理和一致性边界

## Request / Response
- 保持现有定义方式
- 不改对外字段名
- 不为“更优雅”破坏兼容
- DTO / Request / Response 注释说明用途、调用场景、字段含义、来源、单位、枚举、默认值或前后端映射
- 对外字段新增、删除、改名或 tag 变更时，同步检查注释、前端调用、handler 解析、service 校验和 repository 写入
- 新增字段必须明确是否必填、默认值、兼容旧客户端行为和空值语义

## 校验与错误
- 参数校验风格一致
- 错误返回格式、错误码、错误信息风格一致
- 校验失败优先快速返回，不继续执行昂贵 I/O 或数据库操作
