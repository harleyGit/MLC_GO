# 全量离线迁移与逐业务灰度切换方案（尚未执行）

## 边界和数据源

当前旧系统并不是一个统一 S3 桶：`users.avatar_url` 可能指向本地文件；`mall_product_image` 用 `storage_key`、`user_id` 和 `product_id` 表示商家图；`product.image_urls` 等保存 URL；`video_files.file_path` 可指向本地路径或对象存储；`im_private_attachment` 以二进制 ID、会话 ID、封存键和 `im_message_attachment` 保存私有关系。另有商城、评论、类目等 URL 列。**禁止从任意 URL 下载并信任 owner、Bucket、MIME；也不能仅凭可见 URL 推断对象属于哪个租户或商品。** 老 IM 的 `owner_id` 上限 128、商城 `user_id` 上限 255，而新媒体 `owner_id` 上限 64；长度超限、跨租户、缺少源对象或无法验证归属的记录须进入人工审计，不得截断或自动跳过并宣称迁移完成。

## 离线批次流程

1. 在明确授权的隔离环境冻结快照或用主键游标分页导出，每批最多 500 行；建立 `source_type + source_pk` 唯一检查点，记录版本/来源、旧业务槽、上传者、租户、源对象定位、摘要、目标 `asset_id` 和状态，使用受控环境加密存放；日志不输出 URL、会话成员或个人标识。只从权威业务表和合法存储 API 读取，不扫描公开 URL 或任意绝对路径。
2. 按 source 类型分别验证：用户头像关联本人用户行；商城图通过商品/店铺授权及历史订单引用；视频仅处理已确认的视频源、封面、字幕并保留转码依赖；IM 附件必须验证会话成员及消息关联且沿用原 IM 接收方授权，不能简单暴露统一下载。去重仅在同源对象及相同权限域内进行，同一旧对象由多个 SKU/消息引用时逐条建引用。
3. 由授权迁移器流式读取并限制并发、大小和重试，先存到新隔离桶的新随机 Key，再用可信审核器扫描、复核 SHA256/实际 MIME/大小、封存；任何失败保留旧读路径和检查点，标记待审，不能标记 `ready`。新对象上传后发生数据库失败时进入过期清理，不回滚旧数据。
4. 在同一个 MySQL 实例/事务内锁定业务主表，重读当前版本/旧槽，验证上传者资格、租户和 `ready` 资源，调用内部 `HGReplaceReferenceTx` 并原子切换业务主表引用；若旧业务表尚无 asset ID 列，先通过独立增量 DDL 和双读逻辑灰度接入。跨库业务使用可靠事件/Saga，不假定可跨库提交。旧 IM 二进制 ID 必须持久保存新旧映射；所有消息的成员授权仍由 IM 服务负责。
5. 灰度只按业务域和用户/店铺稳定白名单开启：先影子读取比对旧/新摘要和 ACL，再小流量新写；每阶段观测 P95/P99、审查失败、旧新引用差、对象存储回源与垃圾回收堆积。失败时关闭切流旗标恢复旧读写，新对象进入清理；保护期结束前、订单/审计保留未确认前不得清理旧路径。CDN 与短时签名 URL 的过期窗口分别评估。
6. 分批对账：每批核对源条数、检查点、待审/拒绝、成功绑定、未绑定、孤儿对象、共享引用数及授权负向用例；确保跨租户/跨会话无法读，再经批准标记完成。全量结束后对新旧数据做抽样及按主键游标的可恢复全量校验，旧数据删除必须单独审批和备份恢复演练。

## 当前缺口

本轮只交付新表结构、审核/清理/引用原语及离线计划；**没有执行任何旧库查询、旧文件拷贝或切流**，也没有权威来源适配器、迁移检查点表、具体业务字段切换、跨库 Saga、自动清理旧资产或证明 IM 接收方授权等价。全量迁移不能在缺少目标环境、来源范围、审计保留和真实审核器验收时安全自动执行。后续实施顺序：完成审核器端到端契约 → 逐业务字段/权限适配和幂等检查点 → 离线迁移器与小批演练 → 灰度切流 → 延迟清理。
