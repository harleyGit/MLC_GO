# LiveKit 录制与复杂房间管理：上线前设计草案

> 仅为方案与验收条件，不是已实现功能或生产授权。现有 `/calls` 仍是双人单聊，`server-sdk-go/v2` 目前仅用于入房 JWT；不得据此开放 Egress、群房或管理令牌。是否录制、同意方式、保留期和费用归属须产品/隐私/运维共同确认后再确定协议与迁移。

## 权威边界与授权

- Go/MySQL 是会话成员、设备、呼叫状态、房间代次、录制申请与同意的权威；LiveKit Room/Egress 是外部执行状态。客户端只能调用受项目 JWT、请求签名、会话成员校验及设备凭据保护的业务 API，**不能取得** `roomAdmin`/`roomRecord`/Egress 管理 Token 或 S3 写入密钥。
- 录制启动前在短事务内锁定房间/呼叫代次并重查本人会话成员、双方同意、绑定设备、未撤销关系、有效期、额度及状态；双人通话不得由一方单独开启。参与者退出、撤销同意、关系解除或终态后不再授权新录制。对存量录制的停止与删除/导出需明确隐私政策，不能用只停发令牌代替停录。
- 复杂房间另定义受控 `roomId + generation + participantId/deviceId` 契约；成员变更、踢人、静音、锁房、人数上限均以当前代次和版本作 CAS，逐项检查资源与操作者权限。避免把平台管理员角色直接等同于房主/参与者。客户端不得指定任意房间名、Egress 输出 URL 或对象 Key。
- Go 为录制分配隔离的私有 S3 前缀和不可预测对象键；LiveKit Egress 使用仅能写入该前缀的独立短期服务身份。结果仍经受控转码/合规检查与只读授权，不能因录制完成就直接公开。限制时长、并发、空间、码率、请求体、单租户额度及成本；不记录音视频、Token、完整签名 URL。

## 幂等、状态与故障恢复

1. 客户端提交作用域为 `(房间代次, 发起人, requestId)` 的申请；同 ID 不同参数返回冲突。事务写入录制意图、同意快照、唯一任务和 Outbox，提交之后才调用 LiveKit。开始、停止、删除分别持久化状态，不在数据库事务中做网络 I/O。
2. Worker 按 `state,next_retry_at,id` 有界领取并设置租约栅栏；使用稳定 `recordingId` 对外部 Egress 请求做关联。在请求超时/响应丢失时先按该 ID 对账 LiveKit 任务，再决定重试，不能无条件重复 StartEgress；并发实例用唯一约束和 CAS 阻止双录。持续心跳、超时、指数退避和耗尽待人工处理均须可观察。
3. 停止与终态先在 MySQL 原子封禁新开始和新入房，再异步 StopEgress/DeleteRoom；只有外部确认、对账及对象校验通过后写完成状态。同一 Egress ID 的重放不重复计费或创建文件。验签 Webhook 只作为加速信号，不是唯一完成来源；按事件 ID、正文摘要、房间 SID/代次和 Egress ID 去重，轮询补偿漏回调。
4. 对象的清理应有保留期、法律保全例外、按 owner/房间索引分批任务和可恢复进度；删除先阻断授权读取，再删 S3，经 HEAD/清单核实后标记已清理。清理失败保留可重试任务，不因延迟而放宽访问；隔离区和封存区都需孤儿对象对账。

## 终态重入控制（当前生产阻断）

- 当前 `internal/modules/im/hg_call.go` 在事务外 CreateRoom，随后签发 60 秒初始 Token；`cleanup_until` 仅 120 秒。LiveKit 可以自主续签，**延长清理窗口不构成可靠撤权**，也不能仅依赖 `DeleteRoom`、Webhook 或旧房间 SID。
- 推荐在媒体入口实现服务端可强制检查的、逐次入房/续签鉴权：将 `(roomId,generation,deviceId)` 与 MySQL 中的 `accepted` 和成员/设备状态绑定；终态先持久化 `revoked generation`，之后任何重连或续签均拒绝。若目标 LiveKit 版本无法在续签路径提供可验证的实时授权钩子，则必须采用隔离房间代次、终态后永久禁止旧房间名重建、撤权后持续拒绝/踢出旧参与者的可实测替代方案；不能宣称现方案已解决。
- 建房和删房须使用代次唯一的房间名，避免旧 Token 重入新实例；回调同时匹配业务代次与 SID。终态发生在建房响应前的竞态必须补偿删除该新房间；失败任务不能丢。并发终态与续签应以数据库版本/栅栏排序，令牌签发前后校验不可省略。
- 放行条件：锁定 LiveKit 服务端及 Web SDK 版本，验证连接后自动续签行为；隔离环境演练旧 Token、续签 Token、断网重连、同名建房、回调乱序/丢失、跨节点并发和服务重启，证明终态后无法重新加入或继续录制，并有超时上界与告警。未满足前保持 pre/prod 门禁。

## 实施顺序与需要确认的选择

1. 明确录制同意/撤回、谁可查询或删除、保留期、成本预算和敏感内容处置；选定 LiveKit 服务端版本及撤权机制。此处改变隐私与权限边界，实施前需明确确认。
2. 根据已确认业务协议评审迁移（录制状态、房间代次、唯一幂等键、任务索引、回调 Inbox）；千万并发/亿级表按独立有界任务、分区与容量实测设计，不先改现有通话表的线上约束。
3. 增加只在服务端调用的 RoomService/EgressService SDK 适配器，复用现有端点验证、超时、禁止重定向、响应限额与最小权限，覆盖成功/超时歧义/重复/乱序/异常终态；使用隔离 debug 进行外部协议与清理验收，再独立评审 pre/prod。
