
# 手机扫码在局域网更推荐这样设计

你现在是：

> Go 后端 + Web 前端都在本地电脑运行，然后手机扫码。

可以做成：

```text
                 ┌───────────────────┐
                 │       Mac         │
                 │                   │
                 │ Go :8080          │
                 │                   │
                 │ Web :5173         │
                 │                   │
                 │ MySQL             │
                 │ Redis             │
                 └─────────┬─────────┘
                           │
                       局域网 Wi-Fi
                           │
                 ┌─────────▼─────────┐
                 │       手机        │
                 │                   │
                 │ 扫二维码          │
                 │       ↓           │
                 │ Web 页面          │
                 │       ↓           │
                 │ Go API            │
                 └───────────────────┘
```

二维码：

```text
http://192.168.1.100:5173/payment/xxx
```

Web：

```javascript
fetch('http://192.168.1.100:8080/api/payment/xxx')
```

Go：

```go
http.ListenAndServe("0.0.0.0:8080", mux)
```

# 八、如果前端和 Go 都在电脑上，其实还有一种更好的方式

如果你的 React/Vite 和 Go 都在 Mac 上，我建议开发环境使用：

```text
手机
 ↓
192.168.1.100:5173
 ↓
Vite
 ↓
/api/*
 ↓
Go :8080
```

也就是让 **Vite 做反向代理**。

例如：

```js
server: {
    host: '0.0.0.0',
    port: 5173,

    proxy: {
        '/api': {
            target: 'http://127.0.0.1:8080',
            changeOrigin: true,
        }
    }
}
```

那么手机只需要访问：

```text
http://192.168.1.100:5173
```

前端：

```javascript
fetch('/api/payment/123')
```

Vite 自动转发：

```text
手机
 ↓
192.168.1.100:5173
 ↓
Vite
 ↓
127.0.0.1:8080
 ↓
Go
```

这样比直接让手机访问：

```text
192.168.1.100:8080
```

更干净。

# 九、如果你说的“支付”是真正的微信/支付宝支付

这个就要再分情况。

如果你的意思是：

> 我电脑本地启动 Go + Web，然后生成一个二维码，手机微信/支付宝扫一扫，手机进入支付页面，同时这个支付流程需要调用我本地 Go API。

**开发测试可以这样做。**

但是正式的微信/支付宝支付系统通常不能简单依赖：

```text
192.168.1.100
```

因为：

```text
192.168.x.x
10.x.x.x
127.0.0.1
localhost
```

都是内网/本机地址，公网支付平台无法直接访问你的电脑。

正式环境一般需要：

```text
手机
 ↓
公网 HTTPS
 ↓
Nginx / Gateway
 ↓
Go Server
 ↓
MySQL / Redis
```

而你现在本地开发可以：

```text
手机
 ↓
局域网 IP
 ↓
Mac
 ↓
Go
```

## 你这个场景可以先做一个最小 Demo

例如 Go：

```go
package main

import (
    "fmt"
    "net/http"
)

func main() {
    mux := http.NewServeMux()

    mux.HandleFunc("/api/payment", func(w http.ResponseWriter, r *http.Request) {
        fmt.Fprintln(w, "Go payment API OK")
    })

    fmt.Println("server: http://0.0.0.0:8080")

    if err := http.ListenAndServe("0.0.0.0:8080", mux); err != nil {
        panic(err)
    }
}
```

然后查 Mac IP：

```bash
ipconfig getifaddr en0
```

假设得到：

```text
192.168.1.100
```

手机浏览器访问：

```text
http://192.168.1.100:8080/api/payment
```

如果手机显示：

```text
Go payment API OK
```

就说明**手机 → Mac → Go**这条链路已经打通了。

之后再把：

```text
二维码
+
React
+
Go API
+
支付状态
+
WebSocket/SSE
```

串起来即可。

如果你要做的是**“电脑网页展示二维码 → 手机微信/支付宝扫码 → 手机页面调用电脑本地 Go API → Go 实时通知电脑网页支付成功”**这一整套，我可以直接按照你现在的 **Go + React 本地工程**给你画出完整架构，并给出一套可运行的 Go/React Demo。
